5. 🎯Задача: Получить доменное имя и настроить утилиту cert-manager внутри кластера, которая должна сгенерировать wildcard-сертификат для полученного домена. \
Мой интернет-провайдер находится за NAT, поэтому веб-приложение k3s не будет доступно из Интернета. Получение доменного имени бесполезно. Решение: Я отредактировал /etc/hosts, чтобы создать внутреннее доменное имя, которое будет работать с самоподписанным сертификатом. Затем установил Cert Manager. Руководство: https://cert-manager.io/docs/installation/kubectl/. Проверка установки cert-manager: \
![](./images/image_4.png) \
Затем нам нужно установить ClusterIssuer и сертификат. Эмитенты и ClusterIssuers — это ресурсы Kubernetes, представляющие центры сертификации (ЦС), способные генерировать подписанные сертификаты, обрабатывая запросы на подпись сертификатов. \
Первый эмитент, selfsigned-issuer, — это ClusterIssuer, который выступает в качестве центра сертификации верхнего уровня для создания исходного самоподписанного корневого сертификата. Второй эмитент, my-ca-issuer, — это эмитент с пространством имён, который использует корневой сертификат, созданный первым эмитентом, для подписи других сертификатов доменных имён.
Цепочка сертификатов работает следующим образом:
![](./images/certificate-chain-of-trust.png) \
В результате должно получиться что-то вроде этого:
![](./images/image_5.png) \

7. 🎯Задача: Создать PV (постоянный том) для базы данных PostgreSQL в манифесте из десятого проекта. \
Создано заявление на постоянный том. Создавать физический том для локального тома не нужно, так как динамический поставщик работает по умолчанию. PVC готов: \
![](./images/image_7.png) \
❗ПРИМЕЧАНИЕ: по какой-то причине k3s не смог смонтировать том в каталог данных Postgres по умолчанию внутри контейнера. Понижение версии с postgres:latest до postgres:16 решило проблему. Причина этого поведения неизвестна:
![](./images/postgres_error.png) \
8. 🎯Задача: Запустить приложение, описанное в манифесте. ❗ПРИМЕЧАНИЕ: k3s использует сетевой интерфейс контейнера Flannel, который выбрал первый сетевой интерфейс хост-машин, то есть NAT, поэтому связь между Pop-Pod не работала. Для решения проблемы использовался флаг `--flannel-iface`. Применённый манифест с развёртыванием:

9. 🎯Задача: Запустить функциональные тесты Postman и убедиться, что приложение работает.
❗ПРИМЕЧАНИЕ: HTTP-запросы по умолчанию блокируются при использовании TLS:\
